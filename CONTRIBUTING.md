# Участие в разработке

## Подготовка

Используйте Node.js 22.9+ (рекомендуется актуальная LTS-версия):

```sh
npm ci
npm run check
npm test
npm run audit:public
npm audit --omit=dev
```

Тесты используют временные папки, вымышленные аккаунты и отдельный хаб на loopback-адресе. Они не запускают Claude/Codex, не расходуют подписки и не подключаются к рабочим серверам. Среда должна разрешать открытие локального порта.

Для ручного просмотра создайте `.env` через `npm run setup`, затем `npm start`. Никогда не подставляйте рабочую базу в тестовую установку.

## Структура

| Каталог / файл | Назначение |
|---|---|
| `server.mjs` | HTTP API, веб-сокеты, координация задач и постоянного состояния |
| `bridge.mjs` | Выполнение задач на подключённом компьютере, доставка событий и результатов |
| `lib/` | Хранение, безопасность, синхронизация файлов, провайдеры и доменные операции |
| `public/` | Веб-интерфейс и мобильная версия |
| `mac-app/` | Нативная оболочка Mac, установщик фонового подключения и сборка |
| `ios-app/` | Дополнительная нативная оболочка iOS и её сборка |
| `docs/` | Лендинг GitHub Pages и инструкции самостоятельной установки |
| `tests/` | Проверки безопасности, чистого запуска и упаковки |
| `scripts/` | Настройка, проверки исходников и локальный просмотр лендинга |

## Изменения

- Меняйте одну область за раз. Поведение, меняющее форматы событий или восстановления, проверяйте на совместимость с уже установленными Connect.
- Для исправления ошибки добавляйте воспроизводящий тест, когда это возможно.
- Проверяйте desktop и узкий экран при изменении интерфейса. Учитывайте клавиатуру, фокус, touch и reduced motion.
- Не запускайте массовое переформатирование больших файлов вместе с исправлением поведения: это затрудняет проверку изменений.
- Не добавляйте внешние адреса хабов, готовые ключи обновлений, личные проекты, журналы и тестовые дампы реальных переписок.
- Резервируйте время на миграцию данных и восстановление после прерывания записи. Повторное подключение не должно повторно запускать уже принятую задачу.

## Что проверяют команды

`check` проверяет синтаксис JavaScript, локальные импорты и ссылки на статические ресурсы HTML. `test` проверяет отдельные правила и API чистого хаба. `audit:public` проверяет исходники на признаки секретов и данных установки, включая новые неотслеживаемые файлы. Это базовые барьеры; они не доказывают отсутствие всех багов и уязвимостей.

Mac и iOS требуют отдельной сборки на macOS. Подписанный релиз, нотариализация Apple, реальный iPhone, производительность больших проектов и работа с подписками проверяются отдельно. Не включайте их в список проверенного без соответствующего запуска.
