# Безопасность

Для чувствительных проектов используйте собственный сервер и доверенных участников. Это исходный код, а не обещание отсутствия уязвимостей или результат независимого пентеста.

## Перед открытием сервера в интернете

- Настройте HTTPS и `PUBLIC_URL` на свой домен.
- Создайте уникальный `TEAM_ROOM_SETUP_TOKEN` до первого входа. Не используйте пример как секрет.
- Создайте пароль владельца; затем настройте собственного Telegram-бота и получателей, если нужен вход по кодам.
- Храните данные на постоянном volume с резервными копиями. Не выкладывайте архивы данных в Git.
- Приглашайте только доверенных людей. Участники пространства работают с общими проектами.
- Выдавайте компьютеру минимальные необходимые разрешения. Режим полного доступа даёт агенту широкие возможности на выполняющем компьютере.
- Проверьте MCP перед включением: это внешние команды и сервисы.
- Не публикуйте подписанные приложения с конфигурацией личного пространства и архивы пар устройств как общую загрузку.

## Проверка исходников перед публикацией

`npm run audit:public` проверяет файлы и статические привязки. Проверка не заменяет ручной просмотр, аудит зависимостей или анализ поведения. Runtime-каталоги, ключи и архивы исключены из Git и Docker context.

## Сообщить о проблеме

Для общих ошибок создайте issue без токенов, приватных переписок и файлов. Для утечки credentials сначала отзовите их на своём сервере. При сообщении об уязвимости используйте приватный канал репозитория, если он включён; не прикладывайте действующие секреты в публичный issue.
