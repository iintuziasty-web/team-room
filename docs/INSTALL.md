# Установка Team Room Community

## Выберите вариант

| Что нужно | Вариант |
|---|---|
| Попробовать на одном компьютере | Node.js и локальный хаб |
| Работать с телефона и нескольких компьютеров | Свой HTTPS-хаб + подключённые компьютеры |
| Отдельное приложение Mac | Самостоятельная сборка под адрес своего хаба |
| iPhone без разработки iOS | Safari → Поделиться → На экран «Домой» |
| Нативный iOS-клиент | Xcode, своя подпись Apple; исходники включены |

## 1. Локальный хаб

Установите Node.js 22.9+ с официального сайта. В папке репозитория:

```sh
npm ci
npm run setup
npm start
```

Откройте `http://127.0.0.1:4173`. Найдите код `TEAM_ROOM_SETUP_TOKEN` в локальном `.env`, создайте своё имя и пароль. Код защищает только первое создание владельца; при обычном входе он не нужен.

По умолчанию хаб не запускает локальные CLI. Подключите компьютер отдельным архивом из интерфейса. Для разработки возможен `TEAM_ROOM_HUB_ONLY=0`, но для общего сервера используйте значение `1`.

## 2. Собственный сервер с HTTPS

### Docker Compose

Нужны Docker, DNS-имя и доступные порты 80/443. Создайте `.env` через `npm run setup` либо вручную с собственным случайным кодом длиной от 24 символов.

В `.env` задайте:

```dotenv
TEAM_ROOM_DOMAIN=your-hub.example
PUBLIC_URL=https://your-hub.example
TEAM_ROOM_SETUP_TOKEN=YOUR_OWN_RANDOM_SETUP_CODE
```

`YOUR_OWN_RANDOM_SETUP_CODE` — обозначение, не готовый пароль. Используйте значение, созданное скриптом настройки. Направьте DNS на сервер и запустите:

```sh
docker compose up -d --build
```

Caddy настроит HTTPS для вашего домена. Хаб и HTTPS-сервис используют отдельные volumes. Создайте резервную копию volume с данными перед обновлением приложения.

### Railway

1. Создайте **новый** проект из своей копии репозитория.
2. Подключите persistent volume к `/data`.
3. Задайте `TEAM_ROOM_DATA_DIR=/data`, `TEAM_ROOM_HUB_ONLY=1`, `HOST=0.0.0.0`.
4. Сгенерируйте собственный `TEAM_ROOM_SETUP_TOKEN` и добавьте его в переменные.
5. Создайте публичный домен и задайте `PUBLIC_URL=https://ваш-домен`.
6. Откройте его и создайте владельца с кодом настройки.

`railway.json` содержит только параметры сборки и health check. Идентификаторов чужого проекта, окружения или volume в нём нет. Не используйте базу готовой установки как шаблон.

## 3. Подключить выполняющий компьютер

1. Войдите на **свой** хаб и откройте «Компьютеры».
2. Добавьте компьютер с понятным именем и правильным адресом этого хаба.
3. Скачайте созданный архив подключения и распакуйте на этом компьютере.
4. Установите Node.js и официальные Claude Code / Codex, если запускаете через обычный архив.
5. На Mac запустите `node install-background.mjs` из папки подключения. После установки LaunchAgent окно терминала можно закрыть.
6. На Windows запустите `node bridge.mjs`; в этом варианте оставьте процесс работающим. Полноценный Windows desktop installer в этот выпуск не входит.
7. Войдите в собственные аккаунты провайдеров через интерфейс хаба или официальные CLI.
8. Выберите компьютер в верхнем правом углу чата.

Архив подключения содержит ваш действующий токен устройства. Передавайте его только на тот компьютер, который подключаете. Не прикладывайте его к issue и не публикуйте в GitHub releases.

### Mac-приложение

Нужны macOS 13.5+, Xcode Command Line Tools, Node.js и интернет для официальных компонентов.

```sh
TEAMROOM_HUB_URL=https://your-hub.example npm run build:mac
```

Сборщик загрузит зафиксированные версии официальных CLI, проверит контрольные суммы и создаст `mac-app/dist/Team-Room-1.0.0-macOS-universal.zip` и DMG. Полная сборка включает Apple Silicon и Intel; `node mac-app/build.mjs --arch=arm64 --no-dmg` позволяет выбрать вариант при установленной переменной `TEAMROOM_HUB_URL`.

Переместите `Team Room Community.app` в «Программы». Откройте «Этот Mac», войдите на свой хаб и подключите этот компьютер. Сборка привязана только к явно заданному адресу.

По умолчанию применяется локальная ad-hoc подпись. Она не является Apple notarization; Gatekeeper может запросить разрешение. Для распространения подписанного приложения используйте свой Developer ID через `TEAMROOM_SIGN_IDENTITY` и собственный процесс notarization.

### Собственные обновления Mac

В общем репозитории нет ключа доверия к готовой службе обновлений. Автообновление программы выключено по умолчанию.

Чтобы сделать свои обновления:

1. Создайте **собственную** Ed25519-пару вне Git, например через OpenSSL.
2. Передайте путь к открытому ключу в `TEAMROOM_UPDATE_PUBLIC_KEY` при сборке.
3. Храните закрытый ключ вне репозитория и подписывайте им описание релиза.
4. Размещайте архив и подписанный манифест в `mac-releases/` собственного серверного хранилища. Формат см. в `mac-app/connector/updater.mjs`.

Новый манифест должен содержать точные `version`, `minimumMacOS`, `sha256`, `bytes`, `path` и `notes`; `path` имеет вид `/desktop/releases/<sha256>.zip`. Конверт: `payload` — base64 JSON, `signature` — base64 Ed25519-подпись **байтов JSON**. Перед распространением проверяйте собранный архив отдельно.

Обновление фонового подключения из собственного установленного приложения остаётся доступным; оно использует только его собственные компоненты.

## 4. Телефон

Откройте **свой HTTPS-домен** в Safari. Нажмите «Поделиться → На экран “Домой”». Войдите в тот же сервер и выберите включённый Mac. Телефон не появляется как выполняющее устройство.

Push-уведомления требуют установки веб-приложения и разрешения на уведомления. Их поддержка зависит от браузера и системы. На своём сервере генерируется отдельная VAPID-пара. Для Telegram нужен собственный бот и свои получатели.

Подробная инструкция нативной сборки: [ios-app/README.md](../ios-app/README.md). Для нативного iOS-клиента задайте `TEAMROOM_HUB_URL`, откройте проект из `ios-app/`, настройте свою Apple-подпись либо используйте `node ios-app/build.mjs --signed` с `TEAMROOM_APPLE_TEAM`. Без подписи архив нельзя просто установить на произвольный iPhone. Мобильный веб-клиент от этого не зависит.

## 5. Файлы, память и расходы

Хаб хранит общую историю, память и синхронизированные файлы. Выполняющий компьютер хранит рабочую копию и временные передачи. Внешний диск выбирайте в «Этот Mac → Перенести на внешний диск…». Перенос выполняется после завершения активной модели; при ошибке автоматические повторные попытки приостанавливаются.

Большой контекст и переход между провайдерами могут потребовать дополнительного чтения и токенов. Смотрите фактические лимиты аккаунтов, не полагайтесь на обещание «бесплатного контекста». Отдельно учитывайте хостинг, диски и платные внешние сервисы.

## Если компьютер красный

Проверьте доступность собственного хаба и фонового процесса на выполняющем компьютере. В native-приложении откройте «Этот Mac → Обновить состояние». Если нужно — включите существующее подключение. Повторно создавать устройство обычно не требуется.

Для диагностики подходят `connection-status.json` и `last-process-stop.json` из папки конкретного подключения. Перед отправкой любых журналов просмотрите их. Не отправляйте `device-config.json`, `.env`, пароли или базу переписки.
